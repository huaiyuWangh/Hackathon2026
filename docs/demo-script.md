# VoiceCopilot 3 分钟演示剧本

原则：不是功能巡礼，是一部 180 秒的微电影——痛点开场、愿景收尾，中间全部真实操作
（无录屏、无预演假动作）。

## 分镜表

| 时间 | 画面 | 台词 / 动作 | 得分点 |
|------|------|-------------|--------|
| 0:00–0:25 | 沙发上，手机弹出 CI 告警 | "下班了，CI 挂了。以前得回电脑前，现在——" | 痛点共鸣 |
| 0:25–0:50 | 对 Mac（或小智设备）说话："看看 CI 为什么挂了，能修就修" | 控制页点亮麦克风 → 智能体应答"收到，我让 Claude Code 看一下" | AI 呈现：意图理解 + 工具自主调用 |

## 收尾页文案（与 pitch 一致）

> **VoiceCopilot** — 对设备说句话，你的 Mac 就开始写代码，结果读给你听。
> 端侧 MCP 让任何灵矓设备获得"无限技能"，bridge 只是第一个。

## 加分桥段（备选，时间富余时插入）

信息不足任务 → 智能体**追问澄清** → 补充信息 → 成功：
"这个测试怎么跑？"（缺信息）→ "在哪个目录？用什么命令？"（追问）→ 补充 → 执行成功。
把已验证的多轮工具调用变成剧情，而不是运气。

## 道具与网络预案

- **显示双冗余**：AirPlay 大屏为主；手机 viewer（`http://<Mac-IP>:8788/viewer`，
  xterm.js 全内嵌离线可用）为备；再不济直接投 Mac 屏幕。
- **手机连不上 viewer**（家庭路由 AP 隔离已实测存在）：改用手机个人热点，
  Mac 加入热点后同一网段无隔离——热点方案与场地无关，是路演首选。
- **任务时长控制**：提前挑好 demo 仓库任务，彩排计时，单任务 40s 内完成（预热依赖缓存）。
- **AI 说话时不可插话**（回声门控半双工，无耳机场景）：等播报句尾停顿后再开口。

## 开场前 10 分钟 checklist

- [ ] `bin/bridge serve` 在用户自己的终端存活（麦克风权限归属）
- [ ] 控制页 http://127.0.0.1:8787 打开，麦克风初始关闭
- [ ] `.env` 凭证有效、灵矓控制台设备在线（有心跳）
- [ ] tmux 会话干净（无上次残留任务）：`tmux kill-session -t ccline` 后由 bridge 重建
- [ ] 手机已连同一网络并打开 viewer 标签页（确认右上角绿灯）
- [ ] Mac VPN 已关闭（曾干扰局域网入站）
- [ ] 大屏 AirPlay 已连接（若用）；HDMI 备线在手
